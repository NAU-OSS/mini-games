# Contributing to mini-games 

Hi and welcome to the mini-games repository! Thank you for wanting to participate in this open source project. 
This document will outline the methods in which contrubutions are made here. That will include bug reporting,
additional game requests, improvements, and code contributions. 
--- 
## Standards for Contributions 

### Issues
- check that issue is not already submitted in the issues tab
- titles must be desciprtive
- comments should include as much detail as needed for a newbie to understand.
  That includes:
    - complete description of issue
    - possible technologies needed/used (#includes)
    - end goal
    - 
### Pull Requests

We will follow the git flow development style

if you want to work on a new feaure, bug fix, or experiment you must create a dedicated feature/develop/bugfix branch.

**follow naming conventions**

when creating a branch make sure to describe the purpose (bugFix, Feature etc.) and add the issue number. 

eg. ``` git checkout -b feature/'issueTitle'```

eg. ``` git checkout -b bugFix/'issueTitile' ```

commits must contain a clear message on what was changed. BE SPECIFIC. what lines were changed and why? what did it do? 

### code style and formatting 
- follow C conventions
- make sure functions are focused ( do not overload a function )
- variable names should be descriptive ( dont use 'x' )
- should contain clear sudo code. 
- comment the Issue number above functions or additions

### Testing 
code must compile with no warnings 

### Bug reporting 
when reporting bugs follow these steps:
create an issue in the issue tracker ( refer to issues section )
- provide a clear description
- include lines containing the issue
- include possible solutions

request reviews
- assign user and write a comment requesting review and feedback
- do NOT bombard the developer with messages, assume they saw it and will get to it when they can

### proposing new features 
- open issue
- request review from code manager
- Receive feature request acceptance BEFORE implementing
   - once received the go-ahead tag the pull request to that issue  

### Community Note 
- BE RESPECTFUL
- welcome others of all levels of experince
- be helpful, make sure your feedback is detailed
- we will NOT tolerate harassment or bullying of any kind!

if you are participating in this project you agree to abide by these standards.
